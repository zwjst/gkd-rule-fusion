# 均衡模式：广告关闭规则审核

本功能为候选选择器审计，不会直接修改 `dist/gkd.json5` 或自动点击任何按钮。

## 已有规则去重

运行 `npm run audit:ad-close`，对照当前导出订阅查找候选选择器的**完全相同**匹配。完全相同不代表语义去重：不同选择器可能匹配同一控件，仍需结合活动、节点树、规则触发时机检查。现有 9 个全局规则组保持不变。

## 准入条件

1. 仅使用明确广告相关的 ID、文字、无障碍描述或经验证的广告容器上下文。
2. 每条拟启用规则需要至少一个正例快照和一个负例快照；记录 App 包名、版本、Activity、节点属性及截图。
3. 普通 X、✕、关闭、close 不得作为无条件全局规则发布；只能在明确广告容器或应用专属页面下启用。
4. 检查与现有全局/应用规则的重叠、重复触发、`disableIfAppGroupMatch`、时间窗口和点击次数。
5. 经过选择器语法校验、GKD 真机导入和点击测试后，才允许修改生成逻辑并提升订阅版本号。
6. 误触风险较高的规则默认关闭，并提供回退方案。

## 使用

```sh
npm ci --ignore-scripts
npm run audit:ad-close
```

输出 JSON 包含每个候选选择器及其现有完全匹配位置。审计是静态检查，不等同于实际有效性验证。

## 后续发布

审核通过的候选应通过个人命名空间接入现有融合构建流程，避免直接手工修改 dist；保持订阅 ID，提升 version，并更新生成物、校验与来源记录。

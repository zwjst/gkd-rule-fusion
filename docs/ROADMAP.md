# 分阶段验收

## 第一阶段：本次交付

- 四个指定仓库真实调查；订阅、许可证声明、README 绑定提交与摘要。
- 不执行上游代码的 JSON5 读取；应用组、全局组分开统计，规则可追溯。
- 应用覆盖、独占、交集；结构与上下文重复分开；潜在冲突不冒充确定结论。
- 保守融合计划、显式审核、个人禁用/替换/新增；过期覆盖报错。
- 测试与 GitHub Actions 审计工作流，锁文件支持计划回滚复现。

## 第二阶段：P0 导出、自动更新与发布（尚未实现）

- 上游更新创建候选 PR，呈现许可证、覆盖增减、规则差异、审核失效和变更日志，不直接更新稳定版。
- 基于设备验证选择主来源/补充组，校验依赖闭包、跨组 scopeKeys、preKeys、共享冷却/计数引用。
- 持久 key 账本，删除后不复用 key；保留类别默认值和用户开关语义。
- 全局组单独选型，验证全局/应用交互和排除名单，不能叠加启用各源全局组。
- 官方 GKD 解析器检查选择器与完整订阅，输出订阅及版本文件，验证未知字段兼容性。
- 每个导出规则映射来源、个人差异、决策和验证证据；许可证变化阻断发布。
- 明确再发布许可、派生来源链、署名、对应源码与构建说明；NOASSERTION 来源不自动发布。
- CI 测试版经审核/回归晋升稳定版；通道 ID 与版本单调递增、原子更新、失败保留上版、版本目录可回滚。
- 完成客户端导入、引用完整性、更新/回滚及真实误触回归后，才宣布完整 P0。

## 第三阶段：P1 深度适配（尚未实现）

选择用户实际使用的 App、版本与具体操作，收集经授权的脱敏正负快照。记录设备/系统/App 版本、预期点击/禁点、命中数和验证时间。快照缺失/版本不符不能算通过。变更重跑相关用例，不能以数量或链接存在代替质量。

## 第四阶段：P2 管理界面（可选，尚未实现）

展示覆盖、来源、实现差异、许可证阻塞、冲突审核、个人覆盖和回归证据。复用核心模型，不绕过验证与发布门禁。

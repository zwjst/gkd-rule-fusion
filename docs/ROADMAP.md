## P0 后续：更新、稳定版与运行回归

- 上游更新产生候选变更，审阅许可证、覆盖增减、引用、个人覆盖失效和隔离变化；不直接跟随浮动分支替换稳定输入。
- 维护已审核提交、App→source 与类别/key 账本。上游新增 App 不得导致静默来源切换、key 含义改变或用户开关错配。
- 实际验证 GKD 客户端导入、版本描述文件与正文更新、失败保留旧版、版本回滚；订阅 ID 固定，内容变化递增整数版本。
- 用正负快照和设备版本验证选择器命中、前置链、共享冷却/计数、活动限制、误触和性能。
- 专门验证单一全局来源与新增补充 App 的 disableIfAppGroupMatch、排除名单、系统/桌面策略交互。
- 完整编译坐标/滑动表达式与版本模式，验证未知/扩展字段和不同客户端版本兼容性。
- 建立实验版到稳定版的实际审核晋升、失败阻断和发布流程；当前无独立稳定版。
- 许可发生变化立即停止受影响来源进入新发布；Lin-arm、木七目前只参与调查，明确许可及发布条件后才考虑纳入。

完成这些检查与发布流程后，才能宣布稳定订阅和完整 P0 就绪。当前不宣称已自动同步上游或通过实机验证。

## P1：个人深度适配

依据用户实际使用的 App、版本和具体操作，收集经授权的脱敏正负快照。记录设备/系统/App 版本、预期点击和禁点、命中数、验证时间。快照缺失或版本不符不能计为通过。变更重跑相关用例，不以数量或链接存在代替质量。

个人覆盖保持独立于上游，旧指纹失效必须重新审核。明确区分研究计划决策与可发布的整 App 策略，不能让研究阶段的选择直接绕过成品检查。
